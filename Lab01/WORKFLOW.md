## 3. 数据事实（阶段 1 已核实）

以下为 `run_eda.py` 实测结果，详见 [`data-Project1/results/logs/eda_summary.txt`](data-Project1/results/logs/eda_summary.txt)。

| 项目 | 实测值 |
|---|---|
| 训练集 | 7368 行 × 2 列（`text`, `target`），无缺失、无重复文本 |
| 测试集 | 2457 行 × 1 列（`text`），无缺失 |
| 类别 | 10 类，每类 705–747，不平衡比 **1.0596** |
| 长度（字符） | 训练集 p50 = 1139，p99 = 13232，max = **160616**；测试集 max = 59302 |
| 头部结构 | **7368 / 7368** 条都存在以空行分隔的头部块（无分隔符的 **0** 条）；正文为空 **12** 条 |
| 头部字段出现率 | `From:` 100%、`Subject:` 100%、`Lines:` 99.48%、`Organization:` 95.81%、`Reply-To:` 18.99%、`Newsgroups:` **0.00%** |

结论与用途：

- 类别高度均衡，**accuracy 是合理主指标**；本实验默认不作类别加权，但未执行类别权重对照，不能把它解释为加权必然无益。
- 长度长尾严重，需留意极长样本对 `sublinear_tf` 等设置的影响。
- 头部块结构可靠，`re.split(r'\n\s*\n', text, maxsplit=1)` 在**全量 7368 条**训练数据上均成立，无分隔符的文档 **0 条**，A1/A2 对照实验可以干净地做。
- **已在阶段 3 修正一处文档错误**：本表此前写「7356 / 7368 条存在以空行分隔的头部块」，与实测不符。真实含义是 **7368/7368 都有分隔**，7356 为「**正文非空**」的文档数。根因是 `eda_summary.json` 的键名 `n_with_header_block` **命名误导**，它实际统计的是 `split_header_body(t)[1] != ""`（正文非空），而非「有头部块」：
  ```python
  "n_with_header_block": int(sum(1 for t in train_text if split_header_body(t)[1] != "")),
  ```
  键名未改（改动需重跑阶段 1，不属阶段 3 范围），此处以文档说明为准。证据：`results/logs/feature_summary.txt`。
- 正文为空的 12 条是按空行分隔规则测得的「仅头部」帖子，`Lines:` 为 0 或 1 提供辅助证据，例：idx=332 `Subject: How can I install the Printshop Deluxe...`、`Lines: 0`。**对 A1（仅正文）的影响**：这 12 条中训练部分 10 条、验证部分 2 条；训练部分另有一条仅含标点的正文被分词器转换为全零向量，因此 A1 训练全零行是 11/5894 ≈ **0.19%**（见阶段 5a 的边界诊断）。
- **实测**：`Newsgroups:` 出现率为 0，仅排除了该显式字段直接携带标签的路径。**未核验**：该字段是否由官方剥离、是否存在近似重复、作者/机构或邮件线索造成的其他泄露与来源相关性；不能据此宣称「完全不存在标签泄露」。
- 标签是裸整数，类别名为**启发式推断**（非官方映射）。class 7、8 的置信度低于其余 8 类，报告中引用时须注明。

## 4. 实验规范（PDF 强制）

| 规范 | 要求 | 落地做法 |
|---|---|---|
| 三个子集职责分离 | 训练集学参数；验证集选超参；测试集封存到最后 | 自行从训练集切 20% 作验证集 |
| 预处理防泄露 | 均值 / 方差 / **词表**等统计量只能在训练集上拟合 | `fit_transform(X_tr)` 后，验证与测试只 `transform` |
| 一次只改一个因素 | 其余条件保持一致 | 按实验矩阵逐项对照 |
| 先基线后改进 | 先跑通简单基线，再判断新方法是否真有改进 | 朴素贝叶斯作基线 |
| 不根据结果改标准 | 指标与比较方式实验前确定 | 已在 `config.py` 写死 accuracy + macro-F1 |
| 可复现 | 固定种子、记录版本、避免绝对路径 | 种子集中管理 + `environment.yml` |
| 解释结果来源 | 用错误分析、对照实验、消融实验解释 | 混淆矩阵 + 错分样本检视 |

常见误区（PDF 点名）：**在划分前**对全部数据去重、统计、归一化或增强，会把本应不可见的信息带入训练。

## 5. 阶段协议

阶段 0–8 共 9 个阶段。每个阶段结束运行 `check_rigor.py`，未通过不得进入下一阶段。

### 阶段 0 · 环境准备 — 已完成

`environment.yml` 是环境的权威定义。**只用 conda，不用 pip。**

```bash
conda env create -f environment.yml
conda activate project1
```

关键约束：BLAS 后端必须是 **OpenBLAS**，不能是 conda-forge 默认的 MKL。

- 原因：MKL 构建在本机首次调用 BLAS 时原生崩溃（`0xc06d007f`，MSVC 延迟加载失败），无 Python 异常可捕获。
- 迷惑性：崩溃点常出现在 matplotlib 渲染路径（其 transform 内部调用 `np.dot`），极易误判为「matplotlib 坏了」。
- `environment.yml` 已用三条 pin 强制 OpenBLAS：`libblas` / `libcblas` / `liblapack` 均 `=*=*openblas`。
- 不要依赖 `pip freeze`：本环境会输出 `@ file:///D:/bld/...` 形式的本地构建路径，他人无法安装。

### 阶段 2 · 划分验证集 — 已完成

产物：`results/logs/` 的 `split_summary.json`、`split_summary.txt`。

实现：`data_split.py` 是**唯一的划分入口**（`get_split()`），`run_split.py` 执行划分、跑断言并落盘证据。

```python
# data_split.get_split() 的核心逻辑
X_tr, X_val, y_tr, y_val = train_test_split(
    df["text"], df["target"],
    test_size=config.VAL_SIZE,      # 0.20
    random_state=config.SEED,       # 42
    stratify=df["target"],          # 必须分层
)
```

实测结果（SEED=42，VAL_SIZE=0.20，见 `split_summary.txt`）：

| 项目 | 实测值 |
|---|---|
| 训练集 | **5894** 行（79.99%） |
| 验证集 | **1474** 行（20.01%） |
| 类别覆盖 | 两侧各含全部 10 类 |
| 每类占比相对全体最大偏差 | **0.00038**（阈值 0.010）→ 分层有效 |
| 索引交集 / 并集 | 0 / 7368 行（无样本丢失或重复） |
| 划分指纹 sha256 | train `cba4264d…`、val `42afb78f…` |
| 连续两次调用 | 指纹一致 → 可复现 |

约束与说明：

- 必须 `stratify`；划分**必须在任何预处理之前**完成。
- A0–E1 全部对照实验必须调用 `data_split.get_split()`，**不得各自调用 `train_test_split`**：否则各实验划分不同，指标差异无法归因。`check_rigor.py` 第 7 节会机械检查这一点。
- 不落盘索引数组（属中间产物）；划分由 `(SEED, VAL_SIZE)` 完全决定，用指纹作为可比性证据。
- `config.TEST_SIZE` 已改名 `VAL_SIZE`：原名与「测试集」语义重名，而阶段 2 起该值被大量引用，属于易错点。
- 范围收敛：本文档此前写「建议同时试 80/20 与 90/10」。阶段 2 只做 80/20；**90/10 属模型层对照**，需要训练模型才能判断结论是否稳定，故原计划移到阶段 5 的 E 组稳健性实验，阶段 2 不训练任何模型。
  > **补记（阶段 5 自查发现，已闭环）**：该「移到 E 组」的承诺**曾长期未兑现**——
  > E1 检验的是**随机种子**，5 个种子的 `val_size` 全为 0.20，`seed_robustness.json`
  > 中不含 `val_size` 字段。即 90/10 的稳健性一度未被测过，被「种子稳健性」替代而非完成。
  > **现已补做并登记为 E2**（`val_size ∈ {0.10, 0.20}`，见 §5 阶段 5b「E2 组实测结果」），
  > 结论：模型排序在两个比例下均成立。
  > 但 E2 实测到两种比例的划分是**嵌套**的（小验证集 ⊂ 大验证集），
  > 属「截断对比」而非「两次独立重划分」，解读时须注明该限制。
- 承接阶段 1 的约束：`class_top_terms.csv` 是在**全体训练数据**上拟合的。划出验证集后，若用它挑选特征或超参，等于把验证集信息带入选择。该产物只能用于形成**假设**，后续决策只能依据训练集内的统计量。

### 阶段 3 · 预处理与特征工程 — 已完成

产物：`results/logs/` 的 `feature_summary.json`、`feature_summary.txt`。

实现：`features.py` 是**唯一的文本范围与特征化入口**（`featurize()`），`run_features.py` 执行 A0 特征化、跑断言并落盘证据。

**A0 基线配置 = `TfidfVectorizer` 全默认**（在**看到任何结果前**确定，见阶段 6 矩阵）：

```python
vec = features.build_vectorizer()        # 全默认，不传任何参数
X_tr  = vec.fit_transform(train_texts)   # 只在训练集 fit
X_val = vec.transform(val_texts)         # 验证集只 transform
```

| 参数 | A0 取值 | 对应的对照实验 |
|---|---|---|
| `stop_words` | `None` | B1（`None` vs `'english'`） |
| `sublinear_tf` | `False` | B2（`False` vs `True`） |
| `ngram_range` | `(1, 1)` | B3（`(1,1)` vs `(1,2)`） |
| `max_features` | `None` | B4（5k / 20k / 50k / `None`） |
| `min_df` / `max_df` / `lowercase` / `norm` | `1` / `1.0` / `True` / `'l2'` | 结构性选择，不在矩阵中 |

B1–B4 每项**只翻转一个字段**，其余保持上表默认，从而保证对照组可比。

> 早先本节的示例片段把 `sublinear_tf=True`、`stop_words='english'`、`max_features=50000`、`min_df=2` 写成了「默认」，但那两项恰是 B2 与 B1 的变量：固化进基线会让 B1/B2 失去参照点。已按上表改为全默认。

实测结果（SEED=42，VAL_SIZE=0.20，见 `feature_summary.txt`）：

| 项目 | 实测值 |
|---|---|
| 词表规模 | **99,901** 维（默认不设上限） |
| 训练集特征 | 5894 × 99901，nnz = 914072，稀疏度 **0.998448** |
| 验证集特征 | 1474 × 99901，nnz = 214253，稀疏度 **0.998545** |
| 全零行 | 训练集 0 / 验证集 0 |
| 断言 | **7 / 7 通过**（含划分指纹、文本范围计数两项跨阶段核对） |

**防泄露验证（本阶段的关键证据）**：

- 词表**恰等于**训练集 token 集合（99,901 = 99,901）→ 词表只来自训练集。
- 验证集含 33,995 个 token，其中 **7,981** 个在训练集中从未出现。
- **保护强度**：若改用「训练集 + 验证集」拟合，词表将从 99,901 增至 107,882，**多出 7,981 个词**。差值 > 0 说明「只在训练集拟合」是**有效约束而非空转**——这就是「先划分，再预处理」在数字上的意义。
- `transform(X_val)` 不改变已拟合的词表，且重复调用结果一致（幂等）。

约束与说明：

- 绝对不要对验证集或测试集 `fit_transform`；`check_rigor.py` 第 8 节机械检查，含「向量化器只能由 `features.py` 构造」的唯一入口检查（已登记例外：阶段 1 的 `run_eda.py` 诊断向量化器，用完即弃）。
- **不落盘词表与特征矩阵**：属训练中间产物，用完即弃；`feature_summary` 只记派生数值与配置。
- 文本范围三档已全部实现待用：`SCOPE_FULL`（A0 全文）、`SCOPE_BODY`（A1 去头）、`SCOPE_HEADER`（A2 仅头部）。本阶段只验证 A0 路径，A1/A2 对照留阶段 5。
- 无分隔符的 fallback 分支与阶段 1 `run_eda.py` 采用**同一约定**，避免两处定义分歧；该分支实测不可达（0/7368），不影响 A1/A2 语义。

**架构与耗时的关系（实测，用于消除一处看似反常的现象）**：

| D3 配置 | n_iter | 耗时(s) | 首层参数量（99901 × h） |
|---|---|---|---|
| `(100,)` | 20 | 183.3 | 99901 × 100 ≈ 10.0M |
| `(100,50)` | 20 | 183.4 | 99901 × 100 ≈ 10.0M（+ 100×50） |
| `(200,)` | 20 | 361.6 | 99901 × 200 ≈ 20.0M |

`(100,50)` 比 `(100,)` 多一层却耗时几乎相同；从参数规模看，`99901 → 第一隐含层`
主导成本是合理**推断**，两者该层宽度相同；`(200,)` 把该层参数量加倍，测得耗时约 1.97 倍。
这与首层成本主导的解释一致，但未做算子级性能剖析，不能把该原因写成已实测定位。

**耗时并非常量（实测，影响 `max_iter` 上限的解读）**：同一配置
`MLP((100,), max_iter=20)` 在不同时点测得 **183.3 / 212.0 / 414.2 / 446.8 s**（约 2.4 倍），
且波动**也发生在同一进程内**（446.8 → 212.0 → 183.2 s），故不能只归因于供电或热节流。
本仓库未记录 CPU 频率与供电状态，**成因不确定**；详见 `model_timing_probe.txt`。
含义：`max_iter=20` 的数值依据取自偏慢的 414.2 s，因此该上限**偏保守**；
绝对秒数只能用于量级预算，不得当作可复现常量。

**E1 与「同一划分」约束的冲突（本文件早先写法有歧义，此处明确）**：
§5 阶段 2 曾写「A0–E1 全部对照实验必须建立在**完全相同**的划分上」，但 E1 的变量正是种子，

均值 **91,047.2**、标准差 **9,337**、极差 **22,346（约占均值的 24.5%）**。
即「99,901 维」是**该划分特有**的数字，不是本数据集的固有常数——

**F1 组实测结果（特征 × 超参 交互，SEED=42，A0/B2b 特征，见 `experiments_f1.txt`）**：

| 特征 | `C=1`（默认） | `C=10` | `C=100` |
|---|---|---|---|
| A0 | 0.939620（n_iter 40） | 0.939620（293） | **0.940299**（1504） |
| B2b | **0.945047**（40） | 0.943691（280） | 0.943012（1571） |

**主要发现（这是一处反直觉结果，也是本实验较好的独立思考素材）**：

- **`C` 的效果方向随特征翻转**。在 A0 上，val acc 随 `C` **非降**（C=100 最高，+0.0007）；
  在 B2b 上，val acc 随 `C` **单调下降**（C=100 比 C=1 低 **−0.0020**）。
  即「`C` 越大越好」这个在 A0 上得出的结论**不能搬到 B2b 上**——这正是交互效应，
  单因素实验（D1 固定 A0、B2 固定默认 `C`）**原理上无法发现**。
- **把「最优特征」与「最优超参」直接拼起来反而更差**。若按「B1–B4 挑最优特征、
  D1 挑最优 `C`」的朴素做法，会得到 B2b + C=100 = **0.943012**，
  它低于 B2b + C=1 的 **0.945047**（差 −0.0020）。
  朴素拼装不但没有增益，还**比 5a 已有的最好结果更差**。
- **组合搜索没有找到比 5a 更好的方案**。全网格最优是 `F1_B2b_svc`（B2b + 默认 C=1）
  = 0.945047，与 5a 记录的 B2b+svc 完全一致（同配置同值，已由断言交叉核验）。
  即阶段 6 的最优配置就是**已在 5a 测过的那个**。
- **限制**：F1 六个格子只在 seed=42 上比较，观察到了 C 的作用方向随特征改变；
  **完整网格的跨种子交互与统计显著性均未检验**。E1 的跨种子 accuracy 标准差只能描述划分波动，
  不足以证明 F1 差异「显著」或「不显著」。保留既定选参规则选出的 B2b+C=1，
  但把它称为「已搜索候选中的验证最优」，不能称为已证明的总体泛化最优。
- B2b 与 A0 在 `C=1` 下的差为 +0.0054；E1 实测 4/5 种子提高、1/5 打平，
  报告引用 0.945047 时须同时说明验证集参与选择与该方向一致性限制。

## 7. 常见错误

| # | 错误 | 后果 | 规避 |
|---|---|---|---|
| 1 | 划分前就做预处理或统计 | 数据泄露，验证结果虚高 | 先划分再 fit |
| 2 | 在验证集上 `fit_transform` | 同上 | 只 `transform` |
| 3 | 用 `SVC()` 默认核替代既定线性 SVM | 偏离既定实验；本项目未实测可比 RBF 性能 | 使用已登记的线性模型 |
| 4 | 用测试集调参或选模型 | 违反 PDF 规范 | 测试集封存 |
| 5 | `predictions.csv` 全是 0 | 占位文件不可提交；无测试标签，实际准确率未知 | 提交前检查 `nunique() > 1` |

| 7 | 报告堆概念无实验证据 | 独立思考 12.5 分丢失 | 每个论断配数据 |

| 9 | 忘记写 README 运行说明 | 代码 10 分丢失 | 随代码一起维护 |
| 10 | 代码里用绝对路径 | PDF 明确反对 | 用相对路径 |

| 12 | 按 PDF 的「5 页」上限展开写 | 与教师更新的 2 页要求不符 | 上限是 2 页，每模型 1 页 |
| 13 | 把「2 页」当成 PDF 原文 | 溯源混乱，交接时无法自证 | 注明来源是教师后续更新 |
| 14 | 各实验脚本各自调用 `train_test_split` | 划分不同，指标差异无法归因 | 只走 `data_split.get_split()` |
| 15 | 自检脚本因产物缺字段而抛异常崩溃 | 报告停留在上一次内容，本次违规被掩盖成「旧 PASS」 | 每个检查独立 `try`，异常记为 ERROR；反向测试须校验报告是否被重写 |
| 16 | 改动种子 / 划分 / 特征后未重跑基线 | 后续对照以过期基线为参照，结论无效 | `check_rigor.py` 第 9 节复算基线并比对记录值 |
| 17 | 把「跑到 `max_iter` 上限」当作「模型已收敛」 | 把未收敛值当收敛值报告，结论不可靠 | 记录 `n_iter` 与 `converged`（阶段 5 的 MLP 即一例），未收敛必须标注 |
| 18 | 只在一个模型上做特征消融就下结论 | 结论可能**依赖模型**（B1 停用词即反例：NB 升 0.021、LinearSVC 基本不变） | 特征组至少跑两个模型，与模型组交叉验证 |
| 19 | 自检里写下恒真断言（如 `all(True for _ in ...)`） | 检查形同虚设，违规照样「通过」 | 反向测试：故意制造违规，确认真的报 ERROR |
| 20 | 给特征消融设「重试/放宽」式的兜底逻辑 | 一次改多个因素，指标差异无法归因 | 每个配置登记 `changed_keys`，机械比对 `get_params()`，多改一个即断言失败 |
| 21 | 跨阶段断言默认「每个分组都复算了基线」 | D 组不训练 NB，断言 `KeyError` 崩溃，15 次拟合（含约 22 min MLP）在落盘前全部白跑 | 断言不得假定某行必然存在；缺失时降级为「核验已落盘产物」并如实标注走了哪条路径 |
| 22 | 把「实验发现某结论不稳定」当成流程违规报 ERROR | 诚实的结果被标为错误，反而诱导人去掩盖它 | ERROR 只留给「产物与数据不符」；实验结果本身记为**有正当理由**的 WARN |
| 23 | 以为比对结构（seed / 引用 / 超参 / 行数）就能防篡改 | 把某行 `val_accuracy` 改掉不会被发现，超参曲线可被随意改写 | 关键指标必须**复算比对**；昂贵项（MLP）用 `--deep` 按需复算，常规模式如实申报「未复算」 |
| 24 | 断言阶段的异常不做隔离 | 检查里一个 `KeyError` 就葬送整轮已完成的拟合 | 每个检查在独立 `try` 中执行，异常记为失败断言并如实打印调用位置 |
| 25 | 用 `getattr(mod, "NAME", [])` 兜底读取分组定义 | 属性名写错时静默返回空列表，检查缩成只覆盖一部分分组却仍报 PASS（本仓库实际发生：写了 `GROUP_DEFS_DE`，真实名字是 `GROUP_DEFS_D`，第 10.4 节因此**漏掉整个 D 组**） | 显式列出属性并**核对分组名集合**；属性缺失直接记 ERROR。凡「检查项的覆盖范围」本身也要被断言 |
| 26 | 把不同 `val_size` 当成两次独立划分 | 同一 `random_state` 下 sklearn 在同一排列上截断，两种比例的划分**嵌套**；会把「子集对比」误报成「独立重划分也稳定」 | 实测并记录嵌套关系（`nesting` 字段），自检第 12.4 项比对实测值；报告中注明属截断对比 |
| 27 | 用朴素拼装确定「最优方案」（最优特征 + 最优超参） | 交互效应使拼装可能**比单因素最优更差**（F1 实测：B2b+C=100 比 B2b+C=1 低 0.0020） | 需交互证据时用显式声明的网格实验，不靠拼装推断；单因素结论不得跨因素外推 |
| 28 | 缓存键漏掉一个维度（如 `val_size`） | 新实验的结果**静默覆盖**旧记录，跨阶段核对拿错数据比对且不报错 | 缓存键包含全部影响结果的维度；新增维度时同步更新键与记录字段 |
| 29 | 反向测试靠「备份 + 还原」清理现场 | 还原失败时（备份丢失/被占用）产物被**留在篡改态**，后续自检结果全部失真 | 篡改后优先用**重跑实验重新生成**产物，而非依赖备份还原；做完必须再跑一次自检确认回到 ERROR=0 |
