# Agent 实验行为规范（实验二 · 搜索算法）

本文件约束 agent 在实验二现场的行为。目标是**结论有证据、过程可复现、提交者能解释每一步**。

- 适用范围：本目录（`Lab2/`）及其子目录，包括实验代码目录。
- 任务事实、阶段协议与实验矩阵见 [`WORKFLOW.md`](WORKFLOW.md)；要求的来源、原文抽取与时效见其第 1、3 节。
- **用户当前明确指示优先于本文件。**
- 冲突时的优先级：用户当前指示 > 最新教师要求/群通知 > `实验二要求_new.pdf` > `WORKFLOW.md` > 本文件 > 其他。

---

## 1. 开始工作

- **每次开始实际工作前，先完整读一遍 `AGENTS.md` 与 `WORKFLOW.md`**，不得跳过，也不得凭记忆替用旧版本。
- 读完后确认三件事：当前处于阶段 0–8 的哪一步、上一阶段的完成判据是否满足、本次要跑哪些实验。
- 明确本次目标、拟改动的文件、验证方式；**不顺手修改本次范围外的文件**。
- 遇到要求冲突（PDF / 群通知 / 教师口头更新 / 本文件），比较**来源与时效**后取最新且来源更高者，并在 `WORKFLOW.md` 中注明原要求、新要求与来源；不要默默取用其中一个，也不要默认 PDF 一定最新（实验一已出现报告页数被教师更新覆盖的先例）。
- 收到新的测试用例、新的提交要求或新的评分细则时，先登记到 `WORKFLOW.md` 的未决事项与相应阶段，再动手。

## 2. 证据规则

- **不编造**任何结果、指标、剪枝次数、节点数、引用或「已通过」的记录。
- 每个重要论断都必须能指向具体证据：命令、产物文件、图表或日志。
- 区分并标注 **实测 / 推断 / 不确定**。例：A* 返回最优路径是实测；「该启发函数在所有加权地图上都可采纳」是推断，须给出条件。
- **不把「代码跑通了」当作「结论成立」**；不把中间产物当最终结果。
- 阈值、口径、指标必须在实验前确定并落盘；**不因结果好坏而更改**，改了要说明理由与新口径。
- 引用 PDF 原文时给出页码（PDF 共 17 页）；引用他人转述时标注「未核验」。
- 报告与总结中的数字必须能在 `results/logs/` 中找到对应产物；对不上就先查原因，不要改报告迁就。

## 3. 算法与实验纪律

### 3.1 正确性先于性能

- 性能对比的前提是两边都**正确**。任何「更快」的结论都必须同时核对返回值与朴素基线一致；不一致时先修正确性，**不得当作效率差异报告**。
- 每个性能类实验都要有独立复核：最短路径用 BFS 复核步数，最小代价用 h=0 的 Dijkstra（一致代价搜索）复核，博弈值用 Minimax 与 Alpha-Beta 互核。
- 边界情形与主流程同等重要，至少覆盖：无解、起点即终点、单节点树、只有一条子节点、宝藏取完即终止。

### 3.2 单因素对照

- **一次只改一个因素**，其余条件（输入实例、起点终点、地图、宝藏价值、展开顺序基准、平局规则）必须完全一致。
- 每个配置显式声明 `changed_keys`；执行时机械比对实际生效参数，多改一项即断言失败。
- 同一组实验必须使用**同一输入实例**；随机输入由 `SEED` 确定性生成，输入指纹随产物落盘。

### 3.3 基线

- 先跑通最朴素的版本：Q1/Q2 以 **h=0** 为基线，Q3/Q4 以 **Minimax（无剪枝）** 为基线。
- 改进是否真实存在，要与基线在同一输入、同一口径下比较；**没有基线数字的「优化」不算结论**。

### 3.4 指标与规模

- **主指标是计数类指标**（节点扩展数、剪枝次数、入堆次数），它们是确定性的、可复算的。墙上时钟只作量级参考，且必须记录机器、是否单次、重复次数与波动范围。
- **不得只报一个最好看的用例**。效率比值随输入变化，应报多个确定性随机输入的分布（均值、极差）。
- 题面用例规模过小（例如迷宫可通行格仅十余个、博弈树仅十余个节点），**在题面用例上得出的效率结论无效**，必须自设更大输入。
- 引用节点数时必须同时声明**平局打破规则**与优先队列实现，否则数字不可复现。

### 3.5 唯一实现入口

- Q1 与 Q2 **共用同一个 A\* 实现**，只换启发函数与代价函数；Q3 与 Q4 **共用同一套博弈搜索实现**。
- Minimax 与 Alpha-Beta 必须共用同一套状态与子节点访问接口，使两者只差「剪枝」这一个变量。
- 不为单个题目复制粘贴出第二份搜索代码。确需分化时，说明理由并在 `WORKFLOW.md` 登记。

### 3.6 深度的语义

- Q4 的 `H` 是**双方合计的选择步数（ply）**，不是每方回合数；该口径已用 PDF 期望输出验证，改动口径必须重新验证并说明。
- 报告 H 相关结论时，说明 H=4 在本题已达完全搜索（4 个宝藏取完即终止）。

## 4. 环境纪律

- **只用 conda，不用 pip**；`environment.yml` 是环境的权威定义。
- 不引入搜索/博弈相关的第三方库：算法必须自己实现，用现成库既拿不到代码实现分，也无法解释搜索过程。绘图与统计库按需引入，并同步更新 `environment.yml` 与 README。
- 不生成 `pip freeze` 式的依赖清单（会写死本地构建路径，他人无法安装）。
- 依赖标准库行为（如 `heapq` 的元组比较、相同 `f` 时的顺序）时，**先用小探针确认实际行为并落盘**，不要凭印象写结论。

## 5. 记录与产物

- 每次实验记录：输入来源与指纹、处理方式、环境、运行命令、关键参数、随机种子、指标数值、断言结果、退出码。
- 结果落盘到 `results/`，不只留在终端输出里。**没有落盘的数字在报告里不可引用。**
- 保持**相对路径**，脚本在代码目录内运行；不依赖当前工作目录之外的文件。
- 所有随机性通过 `config.py` 的 `SEED` 控制，不在脚本内散落魔数。
- 不落盘无用的大体积中间产物；自设输入记录生成参数与指纹，不提交大文件。
- 不在交付物中放置密钥、私人材料、虚拟环境、缓存或系统元数据。
- PDF 原文抽取、渲染图、诊断脚本放在 `tmp/`，并标明它们**不属于交付物**。

## 6. 测试用例与官方材料

- 用例文件视为**只读**：原样复制到代码目录，逐文件计算 sha256，不修改、不重命名、不「顺手修正」格式。
- 用例与实现不一致时：**改实现，不改用例**。
- 未收到官方用例文件时（见 `WORKFLOW.md` U1），**不得声称「测试用例已通过」**；自造用例必须显式标注为「自设」，不得与官方用例混在一起汇报。
- 复现官方期望输出失败时，先定位是实现错误还是对题面的理解错误，并把定位过程记录为证据。

## 7. 监控与自检

- 每个阶段结束时运行 `python check_rigor.py`（在代码目录内）。该脚本**尚未存在**，属阶段 0 的交付物：在写第一行业务代码前先建立它，并随阶段推进补齐检查项。
- **存在 ERROR 时不得进入下一阶段**：先修复，或如实说明并取得用户确认。
- WARN 必须逐条给出正当理由；无法解释的 WARN 视为未通过。
- 自检脚本覆盖不到的方面（例如：讨论是否恰当、结论是否过度外推、图是否真的可读），由 agent **自行申报**，不得默认通过。
- **不得为了让自检通过而弱化检查项、改写断言或删除产物**；修改 `check_rigor.py` 的判定逻辑需明确说明理由。
- 反向测试：新增或修改检查项后，故意制造一处违规，确认它真的报 ERROR；**一次只制造一处违规**，否则无法判断是哪条检查在起作用。
- 检查项要覆盖自己的覆盖范围（例如断言「实际被执行的分组集合」等于「声明的分组集合」），避免某组被静默跳过却仍报 PASS。

## 8. 交付与沟通

- 交付时说明：改了哪些文件、验证了什么、结果如何、**还有什么未验证**。
- 缺用例、缺算力、缺信息时，如实记录未验证项及其影响，**不拿无关检查冒充验证**。
- 结果不理想、优化无效、剪枝收益为负时，照实报告，不美化、不挑选有利数字而不作说明。
- 「性能不按速度或节点数量简单排名」（PDF 第 17 页）不等于不用给数据：不排名，但必须给出可比较的数字与解释。
- 面向用户的汇报用**简体中文**；不使用 emoji。
- 报告交付前逐项对账：报告数字 ↔ 产物 ↔ 命令，三者一致。

## 9. 禁止事项

- 伪造或「预估」任何指标数值（节点数、剪枝次数、耗时、得分、正确率）。
- 在题面小用例上得出并宣称效率类结论。
- 把「跑出了一个结果」当作「结论成立」，或用一次运行的数字代表整体表现。
- 硬编码应当计算得到的结果（如 Q4 的 6×6 距离矩阵）。
- 修改官方测试用例、或声称已通过实际未运行的用例。
- 为了让结果好看而更换口径、指标或输入（实验后调整比较标准）。
- 声称跑过某实验但实际未运行；把自设用例写成官方用例。
- 未做视觉检查就声称图表正确；未做干净环境复现就声称可复现。
